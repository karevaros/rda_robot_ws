## 1. 조절하는 법 (종전 방식 그대로)

작물 형상은 `obstacles.yaml` 의 `crops.template` 한 곳에서 정한다. 조절 가능한 줄에는
**`@tune=<id>|<min>|<max>|<기본값>`** 마커가 붙어 있고, GUI 가 그 줄의 **숫자만** 바꿔 저장한다.
`obstacle_publisher` 가 ~1초 안에 다시 읽어 RViz 에 반영된다(주석·구조는 보존).

```bash
# 장면 표시
ros2 launch rda_robot_description rda_robot_display.launch.py robot_config:=detail
# 튜너 (인자 없으면 정본 obstacles.yaml)
ros2 run rda_robot_bringup crop_tuner.py \
  ~/robot_ws/src/rda_robot_description/config/obstacles_detail.yaml
```

⚠ 튜너 제목표시줄과 안내에 **어느 파일을 만지는지** 표시된다. 생성물(파생 장면)을 열면
**빨간 경고**가 뜬다 — 거기 넣은 값은 생성기를 다시 돌리면 덮어써진다.

## 2. 조절 가능한 값 (총 19개)

기존 13개(줄기·화방·열매·배치)에 더해, 2026-08-21 사진 대조로 **6개**가 늘었다.

| id | 뜻 | 범위 | 정본 기본값 |
|---|---|---|---|
| `rachis_radius` | 화방대 굵기 (m) | 0.001~0.012 | 0.004 |
| `rachis_z_frac` | **화방대 축 높이** — 열매 반경의 배수 | 0.0~2.0 | **0.0** |
| `rachis_droop` | 화방대 처짐 (m) | 0.0~0.08 | 0.0 |
| `rachis_segments` | 화방대 마디 수 | 1~6 | 1 |
| `pedicel_radius` | **소과경 굵기** (m · 0=없음) | 0.0~0.006 | **0.0** |
| `pedicel_min_len` | 이보다 짧으면 자루 생략 (m) | 0.0~0.03 | 0.008 |

**`rachis_z_frac` 가 핵심이다.**
`0` = 축이 클러스터 **중심**으로 간다(종전 — 축이 열매 속을 관통했다) ·
`1` = 열매 **윗면(+z 표면)** = 사용자 지시값 ·
`>1` = 윗면보다 위 → 소과경이 길어져 사진의 '매달린' 모습에 가까워진다.

🔴 **불리언이 아니라 연속값으로 만든 이유** — 튜너가 숫자만 읽는다(`VAL_RE` 는 `key: 숫자`
줄만 잡는다). `rachis_on_top: true` 로 뒀다면 GUI 에 아예 안 뜬다.

⚠ **`rachis_droop` 와 `rachis_z_frac` 는 서로 물린다.** 축을 열매 윗면(`z_frac=1`)에 얹으면
축 양 끝이 이미 최상단 열매 윗면 높이라, **처지는 순간 축 중간이 그 열매를 파고든다**
(실측: 처짐 3cm 에서 **1.3cm 침투**). 처짐을 보려면 `z_frac` 을 함께 올릴 것.
튜너가 두 값이 동시에 0 이 아니면 **주황색 경고**를 띄운다.

⚠ `rachis_segments` 를 2 이상으로 하면 화방대 이름이 `rachis_<키>_s0/_s1…` 로 갈린다.
데모는 `_stalks_of()` 가 목록으로 찾아 대응하지만, `rachis_<키>` 하나를 가정하는 외부
도구가 있다면 그쪽을 확인할 것.

## 3. 파생 장면 — 손으로 복사하지 않는다

정본을 복사해 변형본을 만들어 두면 **정본이 바뀔 때 조용히 낡는다.** 그래서 차이를 코드로
적고 생성기로 만든다.

```bash
python3 docs/scripts/gen_scene_variants.py           # 생성/갱신
python3 docs/scripts/gen_scene_variants.py --check   # 낡았는지만 확인(exit 1 이면 낡음)
```

| 파일 | 정본과의 차이 |
|---|---|
| `obstacles_real_truss.yaml` | `first_z` 0.10 → **0.35**(현실 화방 높이) |
| `obstacles_detail.yaml` | `rachis_z_frac` **1.0** · `pedicel_radius` **0.002** |
| `obstacles_detail_real.yaml` | 위 둘 다 |

🔴 생성기는 `yaml.safe_dump` 를 쓰지 않고 **줄 단위로 숫자만 치환**한다. dump 로 다시 쓰면
**주석과 `@tune` 마커가 전부 날아가** 파생 장면을 튜너로 조절할 수 없게 된다.
실측: 네 파일 모두 마커 **20개**가 그대로 남는다.

⚠ 생성기가 바꾸려는 키가 정본에 없으면 **에러로 멈춘다**. 새 파라미터는 반드시
정본에 **중립 기본값 + `@tune` 마커**로 먼저 넣을 것 — 그래야 튜너에도 뜬다.

## 4. 정본이 안전한 이유

새 키의 기본값은 **전부 중립**(`rachis_z_frac 0` · `pedicel_radius 0`)이다.
그래서 정본 `obstacles.yaml` 의 **전개 결과가 수정 전 코드와 바이트 동일**하다
(수정 전 `obstacle_publisher.py` 를 git 에서 꺼내 대조 — 187개 동일 ✅).
⇒ 기존 검증 수치(Gazebo/Isaac/Unity 온실 186 primitive 등)는 **재생성 대상이 아니다.**

## 5. 꽃받침(calyx) — 넣지 않기로 한 근거 (2026-08-21)

사용자 판단: *"꽃받침은 열매와 화방대가 만나는 지점에 있고 토마토 대비 아주 작아서
로봇 동작에 크게 방해가 될 것 같지 않다."* → **의견이 아니라 문턱값으로 확인했다.**

**측정** = 파지 자세에서 **열매 꼭지**(꽃받침이 붙는 자리 = 열매 +z 극점)와 그리퍼 표면의
**최단거리**. 이 값보다 작은 꽃받침은 **어느 방향으로 뻗든** 닿지 않는다(충분조건).

```bash
python3 docs/scripts/calyx_clearance.py
```

| 접근각 θ | 손가락~꼭지 | 손바닥~꼭지 | 문턱 |
|---|---|---|---|
| −30° | 2.05 cm | 5.97 cm | **2.0 cm** ← 격자 최악 |
| −15° | 2.42 cm | 5.26 cm | 2.4 cm |
| 0° | 2.64 cm | 4.47 cm | 2.6 cm |
| +15° | 2.76 cm | 3.63 cm | 2.8 cm |
| +30° | 2.65 cm | 2.77 cm | 2.6 cm |

**결론**: 탐색 격자 전체의 최악은 **2.0 cm**(θ=−30°). 실제 런에서 **채택된** 각도만 보면
최악이 **2.42 cm**(θ=−15°, 203회 중 5회). Ø70 mm 열매의 꽃받침이 꼭지에서 1.5~2.5 cm
뻗는다면 **문턱 언저리~아래** → 로봇 동작 판정을 바꿀 만한 요소가 아니다.
⇒ **넣지 않는다.** 열매당 primitive 1개(+74 객체)와 **근거 없는 치수 가정**을 더하는 대가에
비해 얻는 것이 없다.

⚠ **보수적으로 잡은 부분**(실제 여유는 이보다 크다): 그리퍼 관절 **0 rad**(가장 닫힌 상태)로
쟀다. 운용 구간은 0.35~1.18 rad 로 더 벌어져 있다.

🔴 **정정** — 이 측정 전에 *"채택 접근의 78 %가 θ>0(위에서 내려꽂음)이니 꽃받침 자리다"* 라고
적었으나 **그 통계는 이 문제와 무관했다**. 고도를 0°→+30° 로 바꿔도 여유가 2.64 → 2.65 cm 로
사실상 안 변한다. θ 는 *팔이 어디서 오는가*를 정할 뿐, *손이 꼭지에 얼마나 가까이 지나는가*는
파지거리(16.72 cm)와 손 기하가 정한다.

**남는 곳 하나 — 이웃 열매의 꽃받침.** 같은 화방의 아래쪽 이웃(f3) 꼭지에서는 그리퍼가
**0.82~1.08 cm** 로 지난다. 다만 이는 **새 문제가 아니다** — 이 모델의 열매는 애초에 서로
겹쳐 있고(중심 5.95 cm < 반지름 합 7 cm, `cluster_gap 0.85` = 의도된 뭉침), 열매를
충돌객체로 켜면 '손에 든 열매 ↔ 이웃 열매' 접촉이 **이미 4.76~11.78 %** 로 잡힌다
(`구성프리셋-선정규칙.md` 4-1). 꽃받침은 그 수치를 조금 키울 뿐 성격을 바꾸지 않는다.

**이 판정으로 답하지 못하는 것**(꽃받침을 넣어도 이 시뮬로는 확인 불가):
- **실기 파지 안정성** — 꽃받침이 패드와 열매 사이에 끼면 미끄러지거나 열매가 상한다.
  이 모델에는 접촉 물리가 없다(Gazebo 중력 OFF·collision 제거 · Unity 물리 시험도 콜라이더 OFF).
- **인지 편향** — 초록 꽃받침이 빨강 열매 윗부분을 가려 중심 추정이 아래로 치우친다.
  확인하려면 Gazebo 재실행이 필요하다.

## 6. 보증하지 않는 것

- **치수는 사진에서 잰 값이 아니다.** 사진에 스케일 기준이 없어 비율조차 신뢰할 수 없었다
  (자동 세그 결과가 사진마다 0.02~0.34 로 튐). 사진이 정한 것은 **구조**뿐이고,
  절대 치수는 기존 근거(AIHub·STEP 실측)와 통상값이다.
- **잎은 없다**(사용자 지시). 통로 쪽 캐노피 깊이가 없다는 한계는 그대로다 —
  회피 비교 해석에 직접 영향(`구성프리셋-선정규칙.md` 4장).
- **꽃받침(calyx)은 없다.** 넣지 않기로 결정했다 — 근거는 5장(문턱 2.0~2.8 cm).
- 소과경은 열매 **윗면 중앙**에 수직으로 붙는다 — 실제 꼭지의 방향·굽음은 반영하지 않았다.
