## 0. 🔴 이 표를 읽는 법 — **3종은 검증 등급이 서로 다르다**

세 환경을 한 표에 나란히 놓으면 **똑같이 검증된 것처럼 읽힌다.** 실제로는 다음과 같이 다르다.
이 절을 표보다 먼저 읽어야 아래 숫자를 오독하지 않는다.

| 환경 | 등급 | 무엇까지 확인했나 |
|---|---|---|
| **Gazebo** | 🟢 **실행 · 수확 실증** | 로봇이 실제로 움직이고, 인지→계획→execute→열매 제거까지 한 사이클이 돈다 |
| **Unity** | 🟡 **실행 검증**(형상·장면) | Unity 가 로봇·온실을 **의도한 형상 그대로 연다**는 것까지. **물리 거동·제어는 미검증** |
| **Isaac Sim** | ⚪ **산출물 + 로컬 검증** · 실행은 **프로젝트 범위 밖** | 파일이 URDF 와 같은 로봇·같은 장면인지까지. **Isaac 에서 열어본 적 없음**(2026-08-16 사용자 결정) |

🔴 **"로컬 검증 통과 = 실행 보증" 이 아니라는 반증이 이 프로젝트 안에 있다.**
Unity 는 Unity 없이 하는 로컬 검증 **14/14 를 통과한 상태**였는데, 실제로 설치해 돌려 보니
**결함 2건**이 나왔다(패키지 모듈 누락으로 컴파일 실패 · 리플렉션 인자 개수와 코루틴 미구동).
⇒ **Isaac 의 23/23 도 "실행하면 문제없다"는 뜻이 아니다.** 표의 Isaac 열을 그렇게 읽으면 안 된다.

## 1. 공통 소스 — 세 환경이 같은 것에서 나온다

세 환경의 산출물은 **손으로 각각 만든 것이 아니라** 하나의 소스에서 생성된다. 이것이 3종 비교가
성립하는 전제이고, 동시에 아래 "형상 일치" 수치가 높게 나오는 이유이기도 하다.

```
통합 URDF (컴포저 산출)  +  config/obstacles.yaml (온실 정의)
        │
        ├── gen_gazebo_world.py   → Gazebo SDF 월드   (+ URDF 를 robot_state_publisher 가 직접 사용)
        ├── gen_usd_scene.py      → Isaac USD 스테이지
        └── gen_unity_assets.py   → Unity 프로젝트
```

| 항목 | 값 | 재현 |
|---|---|---|
| 통합 URDF | 링크 **44** · 관절 **43** · **가동관절 8** | `ros2 run rda_robot_assembler compose_urdf --mounts <mounts.yaml>` |
| 가동관절 8개 | base · shoulder · elbow · wrist1 · wrist2 · wrist3 · rg2_finger_joint1 · rg2_finger_joint2 | 위와 같음 |
| 질량 합 | **73.688 kg** (질량이 정의된 링크 16개 / 전체 44) | URDF `link/inertial/mass` 합 |
| 온실 정의 | primitive **186개** | `config/obstacles.yaml` |
| 기준 TCP (URDF FK) | **[0.2074, 0, 1.2119] m** · link0 = [0, 0, 0.115] | `gen_usd_scene.parse_urdf` + `link_world_tf` |

## 2. 형상 · 장면 일치 — **세 환경이 같은 로봇·같은 온실인가**

이것이 3종 비교에서 **실제로 비교 가능한 유일한 축**이다(제어·물리는 3절 참조).

| 비교 항목 | Gazebo | Isaac Sim (USD) | Unity |
|---|---|---|---|
| **온실 오브젝트 수** | **186** (SDF `<model>`) | **186** primitive | **186** GameObject |
| **가동관절 수** | 8 (URDF 그대로) | **8** (USD revolute) | **8** (ArticulationBody revolute) |
| **프레임 위치 = URDF FK** | ⚪ **비교 대상 아님** — 아래 ⚠ 참조 | **최대 오차 7.24e-08 m** (링크 프레임 44개) | **최대 오차 6.778e-08 m** (검사 프레임 5개) |
| **TCP** | URDF 값 그대로 | **[0.2074, 0, 1.2119]** | **[0, 1.2119, 0.2074]** (Unity RUF 좌표) |
| **질량** | URDF 그대로 | **73.688 kg** = URDF | ⚪ 리포트 항목 아님 |
| **강체 / 아티큘레이션** | URDF 링크 그대로 | **강체 9** (fixed 병합 후 = 1 + 가동관절 8) | **ArticulationBody 43** |
| **충돌체** | URDF collision 그대로 | convexHull 근사 | **21** |
| **mesh** | 23 (원본) | 참조 | **52** (MeshFilter, 시각+충돌 분리 포함) |
| **검증 통과** | — (실행으로 대신함, 3절) | **23 / 23** | **17 / 17** (Unity 없이 돌리면 14/14) |

⚠ **Gazebo 의 "프레임 오차"를 0 이라고 쓰면 안 된다.** Gazebo 는 통합 URDF 를
`robot_state_publisher` 로 **그대로 소비**하므로 프레임이 일치하는 것은 **측정 결과가 아니라 구조상
당연한 것**이다. 반면 USD·Unity 는 URDF 를 **다른 표현으로 다시 인코딩**한 것이라 일치 여부를
따로 재야 했고, 그래서 위 오차 수치는 **USD·Unity 에만 의미가 있다**.
(⇒ 표에 "Gazebo 0.0" 이라고 적으면 가장 정확한 것처럼 읽혀 **오히려 틀린 인상**을 준다.)

⚠ **좌표계가 다르다** — ROS/Gazebo·USD 는 **Z-up(FLU)**, Unity 는 **Y-up(RUF)**.
Unity 열의 TCP `[0, 1.2119, 0.2074]` 는 같은 점을 다른 축 순서로 쓴 것이다.
변환식 `(x,y,z) → (−y, z, x)` 는 **무작위 2000회로 따로 검증**했다(오차 4.4e-16, det = −1 = 손잡이 뒤집힘).

## 3. 실행 · 제어 · 물리 — 🔴 **비교가 성립하지 않는 축**

당초 계획의 비교 항목은 "제어 정확도 · 성능 · 재현성"이었다. 그러나 **제어가 실제로 도는 것은
Gazebo 뿐**이므로, 제어 정확도를 3종으로 비교하면 없는 데이터를 지어내게 된다.
**비교하지 않고, 어디까지 됐는지를 그대로 적는다.**

| 항목 | Gazebo | Isaac Sim | Unity |
|---|---|---|---|
| 로봇이 움직이는가 | 🟢 **예** — ros2_control JTC 로 실제 구동, "Goal reached" | ⚪ 범위 밖 | 🔴 **아니오** — 컨트롤러 없음(임포트까지) |
| 인지(카메라·옥토맵) | 🟢 D435i/D405 depth → 옥토맵 | ⚪ 범위 밖 | 🔴 없음 |
| 수확 사이클 | 🟢 **수확 2 / 시도 2**, 검출 19→18→17 | ⚪ 범위 밖 | 🔴 없음 |
| 중력·물리 거동 | ⚠ **중력·충돌을 꺼서 우회**(Classic 파지 불안정) | ⚪ **미검증** — effort 유도값의 첫 실전 시험이 될 예정이었음 | 🔴 **미검증** — 임포트만 확인 |
| 드라이브 게인 | ros2_control PID | ⚪ stiffness 1e4 / damping 1e3 = **플레이스홀더** | 🔴 미설정 |
| `mimic`(rg2_finger_joint2) | 🟡 **설계상 처리** — `gazebo_ros2_control` 이 URDF mimic 을 대신 다룬다(컨트롤러는 `rg2_finger_joint1` 만 잡는다). ⚠ **따로 실측하지는 않았다** | 🔴 **없음** — USD 표준에 mimic 이 없어 관절 2개가 독립 | 🔴 **없음** — URDF Importer 가 무시 |

**Gazebo 에서만 나온 제어·인지 수치**(3종 비교가 아니라 **단일 환경 실측**으로 적는다)

| 항목 | 값 | 조건 |
|---|---|---|
| 전략 비교 표본 | **216회** | 열매 × 전략 × planner × 반복 |
| `harvest_linear` | 유효 **108/108** · 완전직선 **108/108** · 폴백 0 · 접촉 **0** | ⚠ **ACM 수정 후**의 값 |
| `direct` | 유효 70/108 · 폴백 38 · 계획 1.10s(3배 빠름) | 위와 같은 런 |
| 열매 인지 | 중심오차 중앙값 **1.6 cm** · 가시 열매 재현율 **92%**(25 중 23) | D435i, 설계값 장면 |
| 파지 성립 최소 ρ | **15.7 cm** | 구 영역 ACM |

## 4. 성능 · 재현성 — **명령 한 줄로 다시 만들어지는가**

이 축은 3종 모두 실측 가능하다. 아래는 전부 **2026-08-16 이 PC 에서 잰 값**이다.

| 항목 | Gazebo | Isaac Sim | Unity |
|---|---|---|---|
| **생성 시간** | **0.34 s** | **2.32 s** | **0.77 s** |
| **생성 명령** | `ros2 run rda_robot_bringup gen_gazebo_world.py` | `ros2 run rda_robot_bringup gen_usd_scene.py --out <dir>` | `python3 src/rda_robot_bringup/scripts/gen_unity_assets.py` |
| **검증 명령** | (실행으로 대신) | `python3 docs/scripts/test_usd_export.py` | `python3 docs/scripts/test_unity_export.py --project <dir>` |
| **검증 결과** | — | **23/23** | **17/17** |
| **검증에 시뮬레이터가 필요한가** | 필요(Gazebo) | **불필요** | **선택** — 없으면 14/14, 있으면 17/17 |
| **인도물 크기** | SDF 텍스트(생성물) | **16 MB** | **67 MB** |
| **런타임 기동** | `gazebo_sim.launch.py` | ⚪ 범위 밖 | **6.74 s** (배치모드 1회, 패키지 캐시 있는 상태) |

⚠ **인도물 크기는 '생성 직후' 기준**이다. Unity 는 한 번 열면 에디터가 `.meta`·임포트 에셋을 더해
프로젝트가 **90 MB** 로 늘고, 별도로 캐시 `Library/` **72 MB** 가 생긴다(둘 다 인도 불필요 — 다시 열면
재생성된다). 표의 67 MB 는 `gen_unity_assets.py` 가 막 만든 상태다.

⚠ **Unity 배치 6.74초는 '두 번째 이후' 값**이다. 첫 실행은 URDF Importer 를 git 에서 받고 프로젝트를
통째로 임포트하므로 훨씬 오래 걸린다. 비교에 쓸 값은 **캐시가 있는 정상 상태**의 6.74초다.

**재현성 측면의 공통점** — 세 환경 모두 **손으로 만든 자산이 하나도 없다.** URDF/`obstacles.yaml` 을
고치고 생성기를 다시 돌리면 세 환경이 동시에 갱신된다. 온실 186개가 세 환경에서 같은 것은
"세 번 똑같이 만들었다"가 아니라 **같은 정의에서 세 번 펼쳤다**는 뜻이다.

## 5. 이번 M4 에서 실제로 얻은 결론

1. **하나의 URDF 에서 3종 환경을 자동 생성하는 파이프라인이 성립한다.** 온실 186개·가동관절 8개가
   세 환경에서 일치하고, 프레임 오차는 USD 7.24e-08 m · Unity 6.778e-08 m 로 **수치 오차 수준이 아니라
   부동소수점 한계 수준**이다.
2. **Isaac 런타임 없이도 Isaac 이 여는 파일을 만들 수 있다** — pip `usd-core` 에 `UsdPhysics` 스키마가
   들어 있어 아티큘레이션·질량·관절 한계까지 표준 스키마로 쓸 수 있었다.
   ⚠ 단 **"열린다"는 것은 검증하지 못했다**(범위 밖).
3. 🔴 **로컬 수치 검증은 런타임 결함을 잡지 못한다** — Unity 실측이 이를 증명했다(14/14 통과 후 결함 2건).
   이 프로젝트에서 가장 값어치 있는 부정 결과이며, **Isaac 산출물을 이어받는 쪽에 반드시 전달해야 하는
   경고**다.
4. **제어·물리 비교는 이번 범위에서 성립하지 않았다.** 제어가 도는 것은 Gazebo 뿐이고, 그 Gazebo 조차
   중력·충돌을 꺼서 우회한 구간이 있다. ⇒ 정직한 결론은 *"3종 형상·장면 파이프라인 검증 완료,
   3종 제어 성능 비교는 미수행"* 이다.
