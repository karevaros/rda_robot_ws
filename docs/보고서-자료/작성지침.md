# 보고서 자료 준비 지침 (노트북 Claude Code 용)

> **적용 시점: 2026-08-14 ~ 마무리(8/31).** 개발이 6주차까지 끝나고 7주차가 진행 중인 지금부터는
> "만드는 일"과 나란히 **"보고할 근거를 남기는 일"** 을 한다. 이 문서는 그 규칙이다.
> 상시 지침(`~/robotclode_ws/CLAUDE.md`)의 "보고서 국면" 절이 이 파일을 가리킨다.

## 1. 역할 경계 — 노트북은 보고서를 쓰지 않는다

| | 하는 일 | 건드리는 파일 |
|---|---|---|
| **Cowork 관리 세션** | 보고서·간트·진행표 **작성** | `기계연 파견/마무리-정리보고/연수결과-보고서.html` 등 |
| **노트북(여기)** | 보고서에 들어갈 **근거·수치·그림·문단 초안 생산** | 이 저장소 `src/docs/보고서-자료/` · `_작업기록.md` |

🔴 **노트북은 `기계연 파견/` 아래 문서를 수정하지 않는다**(예외: `_노트북-작업기록.md` 사본 복사).
보고서에 넣을 내용은 **여기서 만들어 두고**, 관리 세션이 `_노트북-작업기록.md` 를 읽어 옮긴다.
→ 그래서 **`_작업기록.md` 에 안 적은 것은 보고서에 실릴 수 없다.** 이 파일들이 유일한 통로다.

현재 보고서에서 비어 있는 칸(`[작성]` 6곳) = **7주차 카드(수행 내용·산출물)** · **마무리 카드** ·
일정표 7주/마무리 행. 즉 지금 노트북이 채워 줘야 할 근거는 **7주차(M4)와 마무리** 몫이다.

## 2. 산출 위치·파일 규약

```
src/docs/보고서-자료/
  작성지침.md          ← 이 파일
  근거대장.md          ← 보고서에 쓰는 모든 수치의 출처·재현 명령 (단일 진실원)
  주차별-초안.md       ← 보고서 HTML 에 그대로 옮길 수 있는 문단 초안
  3종-비교표.md        ← M4 가상환경 3종 비교 (Gazebo·Isaac·Unity)
  후속과제.md          ← 미해결·미검증·범위 외 항목 (정직하게)
src/docs/images/       ← 스크린샷(기존 관행 그대로, 보고서·README 공용)
```

* **파일명 고정**(작업 규칙 3) — `_v2` 금지, 같은 파일을 덮어쓴다.
* 초안은 **HTML 조각이 아니라 마크다운 문단**으로 쓴다(관리 세션이 자기 서식으로 옮긴다).
* 새 수치가 나오면 **먼저 `근거대장.md`**, 그다음 초안. 순서를 뒤집으면 출처 없는 숫자가 생긴다.

## 3. 🔴 수치 규칙 — 이 프로젝트가 반복해 밟은 함정을 보고서에 옮기지 않기 위한 것

**모든 숫자는 3종 세트로 적는다: 값 · 출처 · 재현 명령.**

```markdown
| 항목 | 값 | 출처 | 재현 |
|---|---|---|---|
| 통합 URDF 조립 회귀 | 29/29 | 2026-07-16 실측 | `python3 src/docs/scripts/test_integrated_urdf.py` |
```

지켜야 할 것:

1. **실측한 것만 적는다.** 문서에 적혀 있다는 이유로 옮기지 않는다 — 이 프로젝트는 문서와 실제가
   어긋난 사례를 여러 번 겪었다(`rbpodo_hardware` 미빌드 · `ros2 run assembler` 미동작 ·
   ACM 조작이 줄곧 무효 · 모델 "28종"이 실제 26종).
2. **미검증은 미검증이라고 쓴다.** "될 것이다"를 완료로 쓰지 않는다. 특히 지금:
   * **Isaac Sim 에서 실제로 열어본 적 없음** — 검증한 것은 "USD 가 URDF 와 같은 로봇인가"이지
     "Isaac 에서 잘 도는가"가 아니다. **🔴 2026-08-16 사용자 결정: Isaac 검증은 이번 프로젝트에서
     진행하지 않는다** ⇒ 표기는 **"실행 미검증(프로젝트 범위 밖)"**. 아래 2-1 참조.
   * **실기 하드웨어 미연결** — 배선은 mock 으로만 검증했다.
   * ✅ **Unity 는 해소됨**(2026-08-16) — 설치·라이선스·배치 실행까지 하고 **17/17** 통과.
     이제 "실행 검증됨"으로 써도 된다(프레임 위치 = URDF FK 최대 오차 6.778e-08 m).

2-1. 🔴 **"범위 밖"과 "미검증 부채"를 구분해서 쓴다.** 둘 다 "안 했다"지만 보고서에서의 뜻이 다르다.
   * **범위 밖** = *하지 않기로 결정한 것*(Isaac 실행 검증 — 2026-08-16 사용자 결정). 숨기지 말고
     **결정 사실·결정 시점·인도물·이어받는 쪽이 확인할 것**을 함께 적는다(`후속과제.md` ⚪ 표).
   * **미검증 부채** = *해야 하는데 아직 못 한 것*(실기 하드웨어 연결 등).
   * ⚠ **범위 밖을 "완료"로 바꿔 쓰지 않는다.** 결정했다고 검증된 것이 되지는 않는다.
   * ⚠ 반대로 **범위 밖을 실패처럼 쓰지도 않는다.** Isaac 인도물(USD 산출 + 로컬 검증 23/23)은
     그 자체로 계약된 산출물이다.
   * 📌 **Unity 사례를 근거로 함께 적는다** — Unity 는 로컬 검증 14/14 를 통과하고도 실제 실행에서
     결함 2건이 나왔다(모듈 누락 · 리플렉션/코루틴). **따라서 Isaac 의 23/23 도 "실행하면 문제가
     없다"는 뜻이 아니다.** 이 한계를 명시하는 것이 정직한 표기다.
3. **effort 값(base 64 / shoulder 314 / elbow 121 / wrist 22 Nm)을 제조사 정격처럼 쓰지 않는다.**
   레인보우 공식 제원에 축별 토크가 없어 **URDF 질량·관성에서 유도한 '요구 하한 × 안전계수'** 다.
   보고서 표현: *"물리 시뮬용 유도값(제조사 정격 아님)"*. 토크 기반 제어·안전 정격 근거로 쓰면 안 된다.
4. **부정 결과도 싣는다.** 이 프로젝트의 신뢰도는 거기서 나온다 —
   IK 재시도 가설 기각 · '새 복셀이 막는다' 가설 미지지 · 선택적 ACM 완화 유의차 없음 ·
   RRT/RRTstar 부적합. 실패한 가설을 지우면 남은 수치의 근거도 같이 약해진다.
5. **정정 이력을 감추지 않는다.** 접촉 10건의 원인을 '구 영역'으로 추정했다가 실측으로 뒤집어
   'Cartesian 관절 뒤집힘'으로 규명한 것 같은 사례는 **과정의 품질**을 보여준다.
6. **조건을 함께 적는다.** "완전직선 108/108" 은 *216회 측정 중 harvest_linear 전략, ACM 수정 후*
   라는 조건이 붙어야 참이다. 조건 없는 수치는 다음 사람이 재현하지 못한다.

## 6. 관리 세션으로 넘기는 법

1. 근거·초안을 위 폴더에 쓰고 **커밋**한다.
2. `~/robotclode_ws/_작업기록.md` 에 **한 절**로 요약한다(무엇을·수치·미검증 표시).
3. `cp ~/robotclode_ws/_작업기록.md "$HOME/GoogleDrive/clode/기계연 파견/_노트북-작업기록.md"`
4. 사용자가 Cowork 관리 세션에 아래를 전달한다:

> `_노트북-작업기록.md` 의 최신 절과 저장소 `src/docs/보고서-자료/주차별-초안.md` 를 읽고
> `마무리-정리보고/연수결과-보고서.html` 의 `[작성]` 칸(7주차·마무리)과 일정표 행을 채워라.
> **수치는 초안에 있는 것만 쓰고, 미검증 표시(⚠·"미검증")는 그대로 옮겨라.**
