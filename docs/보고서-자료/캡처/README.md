## 🔴 관리 세션이 알아야 할 것 3가지

### ① CAP-06 은 요청서의 전제와 실제 설계가 다르다
요청서: *"직선이 주 줄기에 막혀 **OMPL이 우회**하는 궤적"*.
그러나 이 시스템은 **접근 구간에서 우회하지 않는다** — 6주차에 정한 구간별 정책이
*"직선 접근은 재계획하지 않는다(곧게 들어가는 게 정의 · 바꾸면 파지 기하가 깨진다)"* 이기 때문이다.
줄기를 피하는 실제 기전은 **접근각 탐색**이다: 여러 (φ, θ) 조합을 시험해 줄기에 막히지 않는
각도를 고르고, 그 각도로 **직선** 진입한다(5주차 ablation: 완전직선 **2/12 → 11/12**).
· 이 컷의 조건: `pregrasp_demo.launch.py loop:=true rviz:=true` · 채택 로그
  **`직선접근 각도 채택: φ=-40° θ=+30° → 직선 Cartesian fraction=1.00 · 접근구간 관절 0.39 rad`**
· ⇒ 슬라이드 설명을 **"OMPL 우회"가 아니라 "접근각 탐색 후 직선 진입"** 으로 쓸 것.
  ("우회"는 home→pre-grasp 구간에서 일어나며, 그 구간은 CAP-05 에 담겨 있다.)

### ② CAP-11 은 규격 미달이다(1500px)
2026-08-16 촬영본을 16:9 로 **자르기만** 했다 — **업스케일하지 않았다**(늘려도 정보가 늘지 않고
흐려지기만 한다). 1600px+ 가 필요하면 `inject_obstacle.py` 주입 런을 다시 돌려 재촬영해야 한다.
⚠ 주입기는 움직임 감지 후 실제 주입까지 **약 23초**가 걸려 타이밍이 불안정하다(근거대장 6-4-2).

### ③ 요청서의 수치 하나가 틀렸다 — "온실 월드(오브젝트 188)"
**188 = 온실 186 + `ground_plane` + `rda_robot`** 이다. 온실 오브젝트 자체는 **186**.
슬라이드에 "온실 오브젝트 188"로 쓰면 틀린다(2026-08-18 `/get_model_list` 실측 · 근거대장 6-1).

## 재현

캡처 도구에 창 크기 지정을 추가했다(2026-08-18):
```bash
python3 docs/scripts/capture_window.py --name RViz --move 1920,0 --size 2560x1400 \
        --settle 3 --out <파일>
```
⚠ `--size` 는 **창을 올리기 전에** 적용된다 — 순서를 바꾸면 리사이즈 재그리기가 캡처에 걸려
화면 절반이 빈 채로 찍힌다.
