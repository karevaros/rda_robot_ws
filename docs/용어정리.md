# 용어 정리 — 온실 모델 요소 중심

> 2026-08-21 · 사용자 요청. 보고서·슬라이드·코드에서 **같은 것을 같은 이름으로** 부르기 위한 표.
> 근거 수치의 출처는 `보고서-자료/근거대장.md`, 형상 파라미터는 `작물모델-파라미터.md`.
>
> 🔴 이 문서가 필요한 이유 — 같은 대상을 문서마다 다르게 불러 왔다.
> 예: *행잉베드 = 거터 = 재배 베드* · *화방 = 클러스터 = 송이* · *화방대 = 화방 줄기 = 꽃대*.
> 보고서에서 섞이면 읽는 사람이 서로 다른 것으로 읽는다.

---

## 1. 온실 구조물 (yaml 에 직접 기술 · 8개)

| 표준 용어 | 영문 | 객체 이름 | 정의 · 실측 |
|---|---|---|---|
| **거터** | gutter | `gutter_front` · `gutter_rear` · `gutter_front2` | 작물을 얹어 기르는 **고설 재배 베드**. 단면 0.24 m · 길이 6 m · **상면 z = 0.92 m**(STEP 실측). 앞줄 `x=+0.83` / 뒷줄 `x=−0.83` / 다음 줄 `x=+2.49`(줄 피치 1.66 m) |
| **레일** | rail | `rail_L0/R0/L1/R1` | 통로 바닥의 난방배관 겸 대차 레일. Ø0.05 m |
| **지면** | ground plane | `ground_plane` | 바닥 z=0 |

⚠ **"행잉베드"·"재배 베드"·"베드" 는 전부 거터를 가리킨다.** 문서에서는 **거터(gutter)** 로 통일한다.
단, 접근 방향을 말할 때의 *"거터 법선"* 은 **거터 상자의 짧은 수평축**(= 작물행에 수직한
수평 방향, 이 장면에서 ±X)을 뜻한다.

## 2. 작물 (파라메트릭 전개 · `crops` 블록)

| 표준 용어 | 영문 | 객체 이름 | 정의 |
|---|---|---|---|
| **주 줄기** | main stem | `stem_r{행}_p{주}_s{마디}` | 거터에서 위로 유인되는 줄기. Ø11.5 mm(AIHub) · 높이 2.2 m · 로그 곡선을 **짧은 원통 마디 6개**로 근사 |
| **화방** | truss / cluster | (객체 아님 — `t{n}` 인덱스) | 한 마디에서 나온 **열매 송이 단위**. 주당 3화방 · 수직 간격 0.25 m |
| **화방대** | rachis (peduncle) | `rachis_r{행}_p{주}_t{화방}` | 주 줄기 → 화방으로 뻗는 **송이의 축**. Ø8 mm. 🔴 **열매 윗면 높이**를 지난다(2026-08-21 교정 — 종전에는 클러스터 중심으로 가 열매 속을 관통했다) |
| **소과경** | pedicel | `pedicel_r{행}_p{주}_t{화방}_f{열매}` | 화방대 축 → **각 열매 꼭지**로 갈라지는 짧은 자루. Ø4 mm. 🔴 사진에서 '갈래'로 보이는 것이 이것이다 — **화방대가 갈라지는 게 아니다** |
| **열매** | fruit | `fruit_r{행}_p{주}_t{화방}_f{번호}` | 대과 토마토. **반경 35 mm**(Ø70 mm, 통상값) · 화방당 3~4개 |
| **꼭지** | (fruit) apex / stem end | (객체 아님) | 열매의 **+z 극점** = 소과경이 붙는 자리 = 꽃받침이 있는 자리 |
| **꽃받침** | calyx / sepal | **모델에 없음** | 꼭지를 덮는 별 모양 잎. 넣지 않기로 결정 → 4장 |
| **잎** | leaf | **모델에 없음** | 사용자 지시로 제외 → 4장 |

**이름 규칙**: `r{행}` 행 인덱스 · `p{주}` 포기(개체) 인덱스 · `s{마디}` 줄기 마디 ·
`t{화방}` 화방 인덱스 · `f{번호}` 화방 안 열매 번호.
예) `fruit_r0_p3_t0_f2` = 앞줄(r0)·4번째 포기(p3)·최하단 화방(t0)·3번째 열매(f2).

⚠ **`_stalks_of()` 는 이 이름 규칙에 묶여 있다** — 열매 이름에서 자기 화방대·소과경을 찾아
접근 궤적에서만 충돌 허용한다. 이름 규칙을 바꾸면 그 매핑을 함께 고쳐야 한다.

## 3. 배치·형상 파라미터 (`crops.template`)

| 키 | 표준 용어 | 뜻 |
|---|---|---|
| `truss.first_z` | 첫 화방 높이 | 거터 상면에서 최하단 화방까지. **정본 0.10 m · 현실값 0.35 m** ⚠ 아래 참조 |
| `truss.spacing` | 화방 수직간격 | 0.25 m |
| `truss.count` | 주당 화방 수 | 3 |
| `truss.fruits_per_truss` | 화방당 열매 수 | 4(짝수 화방은 3) |
| `truss.rachis_out` | 클러스터 거리 | 주 줄기 → 클러스터 중심 옆거리 0.06 m |
| `truss.cluster_gap` | 뭉침 정도 | 열매 중심 간격 ÷ 지름. **0.85 = 서로 겹침**(중심 5.95 cm < 반지름 합 7 cm) |
| `truss.rachis_z_frac` | 화방대 높이 | 열매 반경의 배수. 0=클러스터 중심 · **1=열매 윗면** |
| `truss.pedicel_radius` | 소과경 굵기 | 0 이면 소과경을 만들지 않는다 |
| `span.spacing` | 주간 간격 | 포기 사이 0.4 m |
| `rows[].x` | 행 위치 | 통로 중심에서 작물행까지 가로거리 **0.83 m**(STEP 실측, 고정) |

🔴 **`first_z` 는 값이 두 개다.** 정본은 **0.10 m** 인데, 이는 RB5 도달권(link0 기준 tcp
최대반경 1.138 m)에 최하단 화방을 넣으려고 **현실값 0.35 m 에서 낮춰 둔 것**이다.
⇒ 보고서에서 수확 실증을 인용할 때는 **"낮춘 배치에서 이뤄졌다"** 를 함께 적는다.
현실 높이 장면은 `obstacles_real_truss.yaml`·`obstacles_detail_real.yaml`.

## 4. 모델에 **없는** 것 — 용어는 쓰되 "모델에 있다"고 쓰면 안 되는 것

| 용어 | 상태 | 근거 |
|---|---|---|
| **잎** (leaf) | **없음** — 넣었다가 사용자 지시로 제거(2026-08-21) | ⇒ 통로 쪽 **캐노피 깊이가 없다**. 회피 비교에서 '정면 직선 진입 충돌 0' 이 나온 원인(`구성프리셋-선정규칙.md` 4장) |
| **꽃받침** (calyx) | **없음** — 넣지 않기로 결정(2026-08-21) | 파지 자세에서 열매 꼭지↔그리퍼 여유 **2.0~2.8 cm** 로, 현실 꽃받침이 그 아래. 측정 = `docs/scripts/calyx_clearance.py` · 상세 = `작물모델-파라미터.md` 6장 |
| **곁순·적심** | 없음 | 모델링 안 함 |
| **화방대 처짐** (droop) | **없음** | 축을 열매 윗면에 얹으면 처지는 순간 열매를 파고든다(실측: 3 cm 처짐 → 1.3 cm 침투) |

**캐노피**(canopy) = 잎·줄기·화방이 이루는 작물 덩어리 전체. ⚠ 이 모델에는 **잎이 없으므로**
"캐노피를 재현했다"고 쓰면 안 된다. 쓸 수 있는 표현은 *"줄기·화방·열매를 모델링했다"*.

**적엽**(defoliation) = 수확 화방 주변 잎을 따는 재배 관행. 잎을 뺐으므로 지금은 해당 없음.

## 5. 로봇·접근 용어 (온실 요소와 함께 쓰이는 것만)

| 표준 용어 | 뜻 | ⚠ 혼동 주의 |
|---|---|---|
| **정면 / 거터 법선** | 거터 면에 **수직한 수평 방향**(이 장면 ±X) | 🔴 **`base→열매` 방향이 아니다.** 이 장면에서 두 방향은 **12.7°** 다르다 |
| **접근각 φ·θ** | 정면 축을 좌우(φ)·상하(θ)로 튼 각 | θ>0 = 위에서 내려꽂음 · θ<0 = 아래에서 들어올림 |
| **롤 ψ** | 접근축 둘레 회전 | 파지에서는 **0 고정**(탐색 안 함) · 절단에서는 **계산값** |
| **standoff** | pre-grasp 가 grasp 에서 뒤로 물러선 거리 | 직선 접근 이동거리와 같다 |
| **파지거리** (`grasp_offset`) | TCP ↔ 열매 중심 거리. 실측 **16.72 cm** | 손가락 파지면 면적중심 + **손바닥 여유**가 하한 |
| **화방대 절단** (cut 모드) | 화방대를 잘라 **화방 통째** 수확 | 열매 파지(grasp 모드)와 대비 |
| **수확 대상 줄기** | 목표 열매가 매달린 **자기 화방대 + 소과경** | 접근 궤적에서만 충돌 허용. 주 줄기·다른 화방대는 **장애물 유지** |

## 6. 장면 객체의 종류 (`kind`)

| kind | 뜻 | 충돌객체로 발행? |
|---|---|---|
| `obstacle` | 실제 물체(거터·레일·줄기·화방대·소과경) | 예 |
| `keepout` | 실체 없는 **가상 이동제한** | 예 |
| `target` | 집기 목표(열매) | **기본 아니오** — `publish_targets:=true` 로 켜면 이웃 열매가 진짜 장애물이 된다 |

## 7. 장면 파일 (같은 온실의 변형본)

| 파일 | 화방 높이 | 화방대·소과경 | 용도 |
|---|---|---|---|
| `obstacles.yaml` | 0.10 (낮춤) | 종전 | **정본** |
| `obstacles_real_truss.yaml` | **0.35**(현실) | 종전 | 스탠드 구성 |
| `obstacles_detail.yaml` | 0.10 | **교정 + 소과경** | 상세 화방 |
| `obstacles_detail_real.yaml` | **0.35** | **교정 + 소과경** | 스탠드 + 상세 |

파생 3개는 **생성물**이다(`docs/scripts/gen_scene_variants.py`). 손으로 고치지 말 것.
객체 수: 정본 **187** → 상세 **240**(소과경 53 추가).
