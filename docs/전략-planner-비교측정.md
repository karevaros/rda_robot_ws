# 수확 전략 · OMPL planner 비교 측정 (2026-07-28)

6주차에서 만든 **선택형 수확 전략**(`harvest_linear` / `direct`)과 **OMPL 알고리즘** 6종이
실제로 어떻게 다른지 같은 표본 열매에서 정량 비교했다. 보고·논문용 수치.

> **정정 이력.** 같은 날 오전에 돌린 1차 측정(108회)은 **구 영역 ACM 이 실제로는 안 걸린 조건**
> 에서 잰 값이라 **무효 처리**했다. 원인은 MoveIt 이 쌍별(pairwise) entry 를 default entry 보다
> 우선하는데 코드가 default 만 쓰고 있던 것(§5). 이 문서의 수치는 그 수정 이후 재측정한 것이다.

## 1. 방법

```bash
ros2 launch rda_robot_moveit_config pregrasp_demo.launch.py bench_strategy:=true \
  bench_n:=6 bench_repeat:=3 rviz:=false            # 원자료 → /tmp/bench_strategy.{json,csv}
python3 src/docs/scripts/bench_strategy_report.py src/docs/bench/bench_strategy.csv
```

- 장면 = **설계값 장면**(`obstacles.yaml`, 작물 179개체 · collision object 113개). 센싱(옥토맵) 장면 아님.
- 각 조합마다 **한 수확 사이클 전체를 계획**한다(home→pre-grasp→접근→파지→후퇴→home). 재생·실행은 안 함.
- 접근 구간은 후퇴에서 역재생되므로 경로길이·웨이포인트에 **2회 반영**.
- 계획 파라미터 고정: `plan_time=5.0s`, `num_planning_attempts=5`, `acm_mode=region`(ρ = 열매반경 +
  `region_margin` 3cm), `standoff=0.12`, `grasp_offset=0.13`, `prefer_near_home=true`.
- 지표 정의
  - **성공** = IK + 계획 산출
  - **유효** = 충돌free(안전 기준 재검증 통과) · 접근 구간 검증됨 · **폴백 없음**
    (폴백 = 계획 실패 시 전략이 쓰는 2점 관절보간. 충돌 미검증이고 경로길이를 과소평가한다)
  - **안전 기준 재검증** = 구 영역을 걷어내고 **'전 작물 장애물 + 목표 화방대만 해제'** 로 되돌린 뒤
    궤적 웨이포인트를 다시 검사한다(제안 방식이 실제로 얼마나 안전한지 보는 잣대).
  - **관절길이**[rad] = 웨이포인트 간 관절공간 L2 합 · **TCP길이**[m] = 로컬 FK 로 구한 TCP 이동거리
    (`robot_introspect.fk_pos`. 검증: link0→tcp 최대반경 1.1377m = 기록값 1.138m 일치)
- 규모: 6열매 × 2전략 × 6planner × 3반복 = **216회 계획, 15분**.

## 3. 해석

1. **직선접근 구조가 이 장면을 전부 푼다.** `harvest_linear` 는 6열매 전부에서 **완전직선
   (`cartesian(frac=1.00)`) 108/108**, 폴백 0, 플래너 실패 0. 자유공간 구간(home↔pre-grasp)이
   단순해서 어느 planner 를 써도 계획이 성립한다 — **planner 선택의 영향이 사실상 없다**
   (관절길이 중앙값이 6 planner 모두 3.66 rad 로 동일).
2. **`direct` 는 빠르지만 실패가 잦다.** 계획시간 중앙값 1.10s 로 3배 빠른 대신 **폴백 38/108(35%)**,
   plan_to 실패 42회, 유효 70/108(65%). 열매별 편차도 크다(3/18 ~ 18/18) — 자유공간 직행은
   열매가 줄기 사이 깊이 있을수록 잘 안 풀린다.
3. **경로길이는 harvest_linear 이 짧다.** 접근 구간을 왕복으로 세고도 관절 3.66 vs 3.91 rad.
   TCP 길이는 `direct` 가 짧게 나오지만(1.867 vs 2.088 m) 이는 **유효 행만 평균낸 결과**라
   `direct` 의 어려운 사례가 폴백으로 빠져 통계에서 제외된 탓이다 — 성공한 것만 비교한 값이다.
4. **planner 는 `direct` 에서만 갈린다.** 유효율 PRM 14/18 > RRTConnect·RRT 13/18 > BiTRRT 11/18 >
   RRTstar 10/18 > EST 9/18. 호출 단위 실패율도 PRM 5.6% 가 최저. **RRTstar 는 호출당 5.03s**
   (최적화 planner 라 `plan_time` 을 소진) 로 유일하게 계획시간이 두 자릿수(중앙 10.8~12.8s)다.
5. **🔴 안전 기준으로 되돌리면 접근 궤적에 접촉이 남는 사례가 있다(10건).** 전부 한 열매
   (`fruit_r0_p2_t0_f1`)에서, 그것도 **완전직선(frac=1.00)** 궤적의 웨이포인트 1개가 접촉으로 잡혔다.
   원인은 구 영역 ACM 이 **반경 ρ 안의 이웃 객체까지 통째로 허용**하기 때문 — 계획 때는 허용된
   이웃 화방대·줄기를, 안전 기준(목표 화방대만 해제)에서는 장애물로 보기 때문이다.
   ⇒ **구 대신 접근 축 캡슐/원뿔**로 영역을 좁히자는 기존 개선 아이디어가 수치로 뒷받침됐다.

**권고**: 기본값 `strategy:=harvest_linear` 유지. 이 장면에서는 planner 가 결과를 거의 안 바꾸므로
`planner_id` 는 **빠른 것(RRTConnect·BiTRRT)** 이면 충분하고, **RRTstar 는 4배 느린 값만 치른다**.
`direct` 를 쓸 경우에는 **PRM** 이 가장 안정적이다.

## 4. 남은 과제

- **구 영역 ρ 를 접근 축 캡슐/원뿔로 교체**(§3.5) — 이웃 객체 통째 허용을 줄이면 접촉 10건이 사라질 것.
- 표본 확대 — 현재 base 위치에서 도달 가능한 6열매. base 를 옮겨가며 재면 표본이 는다.
- 센싱(옥토맵) 장면에서 같은 측정 — 설계값 장면보다 장애물이 촘촘해 planner 차이가 더 벌어질 것으로 예상.
- 계획 품질 외 **실행 품질**(execute 시 실제 소요시간·추종오차)은 이 측정에 없다.
- **데모의 도달 판정(`_select_reachable`)은 구 영역 허용 *전*에 IK 를 본다** — 허용 후 판정하면
  도달 열매가 3→6개로 늘었다(측정 표본에서 확인). 수확 파이프라인 동작이 바뀌는 변경이라
  라이브 확인이 필요해 이번엔 손대지 않았다.

## 5. 부록 — 1차 측정을 무효로 만든 ACM 버그 (2026-07-28 규명)

측정 내내 `구 영역 ACM 허용(객체 추가 후 재적용) 실패` 경고가 났다. 진단 스크립트로 ACM 을
단계별로 덤프해 **세 가지가 겹쳐 있었음**을 확인했다.

1. **🔴 쌍별(pairwise) entry 가 default entry 를 이긴다.** 객체가 장면에 들어올 때 로봇 링크와의
   쌍별 entry(False)가 만들어지는데, 코드는 `default_entry` 만 True 로 바꾸고 있었다 →
   **목표 화방대 허용이 실제로는 안 걸렸다**('조용한 무효').
   실측: `rachis_r0_p3_t0` default=True 인데 **로봇 링크 17개 전부와 False**. (구 `harvest_zone`
   자신은 쌍별 False 0개라 정상이었다.) ⇒ 이제 허용/차단할 이름의 **행·열을 직접 써넣는다.**
2. **검증 오류 A — `want=False` 인데 '항목 없음'을 불일치로 판정.** MoveIt 은 중복인 False default 를
   저장하지 않는다(실측: `stem_*` 84개가 매번 누락으로 잡혀 4회 재시도를 낭비).
3. **검증 오류 B — 월드 객체끼리의 쌍까지 True 를 요구.** MoveIt 이 검사하는 건 로봇↔월드와
   자기충돌뿐이라 객체끼리의 False 는 정상이다. 작물 106개를 default False 로 깔아두니 구의 쌍별
   행에 그 False 들이 남아 **항상 실패**했고, `_allow_region` 이 False 를 반환해 `_zone_at` 기록까지
   누락됐다(→ `_clear_zone` 무력화).

**수정 효과(같은 3열매 / harvest_linear / RRTConnect)**

| | 수정 전 | 수정 후 |
|---|---|---|
| ACM 경고 | 매 호출 실패 | 0건 |
| 계획시간 | 11.6~12.3s | 2.5~3.6s |
| `fruit_r0_p3_t0_f1` 접근 | 항상 `ompl-avoid`(우회) | `cartesian(frac=1.00)` |
| 도달 가능 열매(표본 선정) | 3개 | 6개 |

**교훈**: ACM 은 `default_entry` 만으로 판단하지 말 것. 반영 확인은 **로봇 링크와의 쌍별 값**으로 하고,
`False` 는 '항목 없음'과 같은 뜻으로 취급해야 한다. (Stage 5 이래 세 번째 '조용한 무효' 사례.)
