# 수확 전략 · OMPL planner 비교 측정 (2026-07-28)

6주차에서 만든 **선택형 수확 전략**(`harvest_linear` / `direct`)과 **OMPL 알고리즘** 6종이
실제로 어떻게 다른지 같은 표본 열매에서 정량 비교했다. 보고·논문용 수치.

## 1. 방법

```bash
ros2 launch rda_robot_moveit_config pregrasp_demo.launch.py bench_strategy:=true \
  bench_n:=6 bench_repeat:=3 rviz:=false            # 원자료 → /tmp/bench_strategy.{json,csv}
python3 src/docs/scripts/bench_strategy_report.py src/docs/bench/bench_strategy.csv
```

- 장면 = **설계값 장면**(`obstacles.yaml`, 작물 179개체 · collision object 113개). 센싱(옥토맵) 장면 아님.
- 각 조합마다 **한 수확 사이클 전체를 계획**한다(home→pre-grasp→접근→파지→후퇴→home). 재생·실행은 안 함.
- 접근 구간은 후퇴에서 역재생되므로 경로길이·웨이포인트에 **2회 반영**.
- 계획 파라미터 고정: `plan_time=5.0s`, `num_planning_attempts=5`, `acm_mode=region`, `standoff=0.12`,
  `grasp_offset=0.13`, `prefer_near_home=true`.
- 지표 정의
  - **성공** = IK + 계획 산출
  - **유효** = 충돌free(안전 기준 재검증 통과) · 접근 구간 검증됨 · **폴백 없음**
    (폴백 = 계획 실패 시 전략이 쓰는 2점 관절보간. 충돌 미검증이고 경로길이를 과소평가한다)
  - **관절길이**[rad] = 웨이포인트 간 관절공간 L2 합 · **TCP길이**[m] = 로컬 FK 로 구한 TCP 이동거리
    (`robot_introspect.fk_pos`. 검증: link0→tcp 최대반경 1.1377m = 기록값 1.138m 일치)
- 소요: 108회 계획 = **46분**.

⚠ **표본이 작다.** `bench_n:=6` 을 줬지만 현 로봇 위치에서 도달 가능한 열매가 **3개**뿐이라
조합당 9회(3열매 × 3반복)다. **planner 간 순위는 참고용**이고, 강한 차이(RRT/RRTstar 대 나머지)만
신뢰할 만하다.

⚠ **구 영역 ACM 의 쌍별(pairwise) 재적용이 매 호출 실패했다**(`구 영역 ACM 허용(객체 추가 후 재적용)
실패`). 구 자체 허용은 걸린 것으로 보이나(아니면 IK·직선접근이 전부 실패했을 것 — 실제로는
fraction 1.00) **구에 겹친 명명 작물(목표 화방대)은 장애물로 남은 조건**에서 측정됐다.
두 전략·모든 planner 에 동일 조건이라 **상대 비교는 유효**하지만, 절대 성공률은 이 조건에 묶인다.
Stage 5 의 '조용한 무효' 계열 사안 — 별도 확인 필요.

## 3. 해석

1. **직선접근 구조가 경로를 짧게 만든다.** 유효 행 중앙값 기준 `harvest_linear` 관절 **3.56 rad** vs
   `direct` **5.28 rad** — 접근 구간을 왕복(2회) 세고도 33% 짧다. TCP 길이는 2.13 m 대 2.05 m 로 비슷하니,
   차이는 **관절공간에서의 헛된 큰 회전**이 `direct` 에 더 많다는 뜻이다. 웨이포인트도 36 대 44.
2. **`direct` 의 "빠름"은 상당 부분 포기다.** 계획시간 중앙값은 1.69s 대 12.25s 로 7배 빠르지만,
   **폴백이 28/54(52%)** — 절반 이상이 자유공간 계획 실패 후 2점 보간으로 떨어졌다(pre 18 · home 23).
   `harvest_linear` 은 15/54(28%). 유효율은 **39/54(72%) vs 26/54(48%)**.
3. **접근 직선 성립 여부는 planner 가 아니라 장면 기하가 정한다.** 열매 3개 중 2개는 planner·반복과
   무관하게 항상 `fraction=1.00` 직선, 나머지 1개는 항상 OMPL 우회(42점). 즉 직선 접근각 탐색은
   결정적이고, planner 선택은 **자유공간 구간(home↔pre-grasp)에만** 영향을 준다.
4. **이 좁은 온실 장면에서 RRT·RRTstar 는 부적합.** 호출 실패율 55.6% / 59.3%, 호출당 2.8s / 5.0s
   (최적화 planner 라 `plan_time` 을 소진). `harvest_linear/RRTstar` 조합은 계획시간 중앙값이 **36.7s**
   까지 올라간다. 반면 **RRTConnect·BiTRRT 는 호출당 0.14s** 로 두 자릿수 빠르다.
5. **유효율만 보면 PRM·EST 가 근소 우위**(harvest_linear 기준 8/9 · 7/9 vs 나머지 6/9). 다만 조합당 n=9 라
   1건 차이가 순위를 바꾸므로 **현 기본값(RRTConnect)을 바꿀 근거로는 약하다**. 시간·실패율·유효율을
   같이 보면 **RRTConnect / BiTRRT / EST / PRM 이 한 묶음, RRT·RRTstar 가 열등**하다는 것이 이 측정의
   신뢰할 수 있는 결론이다.
6. **안전성은 전 조건 동일.** 충돌 웨이포인트 총 **0건** — 계획된 궤적은 모두 안전 기준(전 작물 장애물 +
   목표 화방대만 해제)에서 재검증을 통과했다. 위험은 충돌이 아니라 **폴백(무검증 보간)** 쪽에 있다.

**권고**: 기본값 `strategy:=harvest_linear` · `planner_id:=RRTConnect` 유지. `direct` 는 대조군으로만 쓰고,
쓸 경우 `BiTRRT`/`EST` 와 묶는다(유효 6/9, 1.2~1.7s). **RRT·RRTstar 는 이 장면에서 쓰지 말 것.**

## 4. 남은 과제

- 표본 확대(도달 열매가 3개뿐 — 로봇 base 위치를 바꿔가며 측정하면 표본을 늘릴 수 있다).
- 구 영역 ACM 쌍별 재적용 실패 해소 후 재측정(절대 성공률이 달라질 수 있다).
- 센싱(옥토맵) 장면에서 같은 측정 — 설계값 장면보다 장애물이 촘촘해 planner 차이가 더 벌어질 것으로 예상.
- 계획 품질 외 **실행 품질**(execute 시 실제 소요시간·추종오차)은 이 측정에 없다.
