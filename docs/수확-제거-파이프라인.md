# 수확한 열매를 장면에서 없애기 (2026-07-29)

실제 수확에서는 **딴 열매가 사라진다** → 그 뒤에 가려져 있던 열매가 보이고, 진입로도 열린다.
그런데 코드는 딴 열매를 그대로 두고 있었다. 그래서 "수확 가능 열매 N개" 는 **한 프레임 정지 장면
기준의 하한값**이었다. 이 문서는 그걸 실제 수확 런처럼 바꾼 내용이다.

## 1. 고치기 전 상태 (실측 확인)

| 층위 | 문제 |
|---|---|
| 계획(planning scene) | `_play_cycle` 이 파지 후에도 열매를 장면에서 빼지 않는다 |
| 재발행 | `obstacle_publisher` 가 **1초마다 전체 재발행**(`period=1.0`) → 지워도 곧 되살아난다 |
| 목록 | `run_harvest_all` 이 수확 가능 목록을 **시작할 때 한 번만** 뽑는다 → 새로 열리는 열매가 후보에 못 들어옴 |
| 인지 | Gazebo 에서 열매가 그대로라 카메라가 계속 본다 → 뒤쪽 열매의 가림이 안 풀림 |

**⚠ 그리고 애초에 열매는 충돌객체가 아니었다.** `obstacle_publisher` 는 `kind: target` 을
CollisionObject 발행에서 제외한다("목표를 장애물로 세면 계획 실패"). 그런데 이 규칙은 **목표가
아닌 이웃 열매까지 전부** 빼버린다 → 이웃 열매를 밀고 지나가는 궤적이 충돌로 잡히지 않는다.

## 2. 바꾼 것

### 열매도 장애물로 (`publish_targets`, obstacle_publisher)

`publish_targets:=true` 면 `kind: target` 도 CollisionObject 로 발행한다. **목표 열매 자신은
구 영역 ACM 이 허용**하므로(반경 ρ 안, `region_max_object` 이하 크기) 계획이 막히지 않고,
이웃 열매만 장애물로 남는다.

- 실측: 켜면 손가락·손바닥이 이웃 열매를 관통하는 궤적이 바로 잡힌다
  (`rg2_leftfinger|fruit_r0_p2_t0_f2×4`, `rg2_hand|…×3`).
- 실측: 수확 가능 열매가 **6 → 4 개**로 준다(원래 6개는 이웃 열매를 무시하고 센 값이었다).
- 기본값은 `false`(기존 측정 기준선 유지). 켜고 재는 것이 '진짜' 기준이다.

### 수확 → 제거 (`harvest_remove`, pregrasp_demo)

`_remove_fruit(name)` 이 **세 곳을 함께** 처리한다. 하나라도 빠지면 조용히 되살아난다.

1. `/harvested` 토픽으로 이름 발행 → `obstacle_publisher` 가 **재발행 제외 목록**에 넣고 REMOVE 발행
   (TRANSIENT_LOCAL 이라 구독이 늦게 붙어도 놓치지 않는다)
2. planning scene 에 즉시 `CollisionObject.REMOVE`(재발행 주기를 기다리지 않게)
3. Gazebo `/delete_entity` 로 모델 삭제 — 열매가 각각 독립 모델(`<model name="fruit_…">`)이라 가능.
   시뮬 미구동이면 서비스가 없어 조용히 건너뛴다.

`reset`(또는 `*`)을 `/harvested` 로 보내면 제외 목록이 비워진다(재생 데모 반복용).
단 **Gazebo 에서 실제로 지운 뒤에는 원복하지 않는다**(되살릴 수 없다 → 시뮬 재시작 필요).

### 매 수확 후 목록 재도출 (`run_harvest_all`)

시작할 때 한 번 뽑아 두고 도는 대신, **수확할 때마다 수확 가능 목록을 다시 뽑는다.**
새로 열린 열매가 그 시점부터 후보가 된다. 실패한 열매는 `failed` 에 넣어 무한 재시도를 막는다.
끝나면 **수확 가능 열매 수 추이**를 로그로 남긴다 — 이게 "앞을 따면 뒤가 열린다" 의 실측 근거다.

### 도달 판정 기준 통일 (07-28 기록의 2순위 항목)

`_select_reachable` · `_is_harvestable` · `run_harvest_all` · 인터랙티브 모드가 모두
**수확 작업공간(구 영역)을 허용한 뒤** IK 를 본다. 예전엔 판정만 허용 전에 해서
'목록엔 있는데 계획에선 도달불가' 가 생겼다(실측: 도달 3개 → 6개).
비용을 아끼려고 **2단계**로 본다 — 허용 없이 통과하면 그대로 통과, 실패한 것만 구 영역을 걸고 재판정.

## 3. 검증 (설계값 장면, 재생 모드)

```bash
ros2 launch rda_robot_moveit_config pregrasp_demo.launch.py \
  harvest_all:=true harvest_max:=3 loop:=false rviz:=false publish_targets:=true
```

```
수확 가능 열매 4 / 전체 74 (워크스페이스 필터)
── 수확 1: fruit_r0_p3_t0_f0 …   수확 완료 → 장면에서 제거 (누적 1개)
수확 가능 열매 4 / 전체 73
── 수확 2: fruit_r0_p3_t0_f2 …   수확 완료 → 장면에서 제거 (누적 2개)
수확 가능 열매 3 / 전체 72
── 수확 3: fruit_r0_p2_t0_f0 …   수확 완료 → 장면에서 제거 (누적 3개)
수확 가능 열매 2 / 전체 71
연속 수확 완료 — 수확 3 / 시도 3 / 건너뜀 0
  수확 가능 열매 수 추이(수확할 때마다 재도출): 4 → 4 → 3 → 2
```

- 제거는 매번 반영된다(전체 74 → 73 → 72 → 71).
- 첫 수확 뒤 **4 → 4**: 하나를 땄는데 수가 그대로 = **새로 하나가 열렸다**(막고 있던 열매가 빠져서).
- 이후로는 새로 열리는 것 없이 줄어든다(3 → 2).

⚠ **이 장면에서는 '막힘' 효과만 측정된다.** 목표를 yaml 설계값에서 읽으므로 **가림(occlusion) 효과는
없다.** 진짜 이득은 인지 장면(`target_source:=perception`)에서 나온다 — 앞 열매를 지우면 카메라가
뒤 열매를 보게 되고 옥토맵도 침식된다. **그 검증은 아직 안 했다(다음 세션).**

```bash
# 인지 장면에서 (Gazebo 필요)
ros2 launch rda_robot_moveit_config perception_demo.launch.py execute:=true run_demo:=true \
  harvest_all:=true harvest_max:=3 harvest_remove:=true gui:=false \
  sensors:=d435i world:=greenhouse detect:=true
```

## 4. 함정 기록

- **측정/데모 스택을 두 개 띄우지 말 것.** 같은 DDS 도메인에서 move_group·obstacle_publisher 가
  둘 뜨면 장면이 섞인다. 실제로 `publish_targets:=true` 로 돌던 다른 창의 발행이 비교 측정에
  섞여 들어와 접촉이 4건 잡혔다(그 실행은 폐기하고 재측정했다).
- `harvest_all` + `loop:=true` 는 다 따고 나면 장면을 원복해 반복한다. Gazebo 삭제를 한 경우엔
  원복하지 않으므로 반복 데모는 `harvest_remove:=false` 나 시뮬 재시작이 필요하다.
